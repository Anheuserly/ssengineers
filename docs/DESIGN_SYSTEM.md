# Design System

## Design intent

The site should feel like a dependable engineering partner: calm, clear and evidence-led. Strong typographic hierarchy and restrained surfaces matter more than decorative visuals.

## Core principles

- Show real project photography only where it represents the work being described.
- Keep service cards media-free until verified listing media exists.
- Use red as an action and safety signal, not as a full-page background.
- Keep conversion actions clear: add to bucket, review bucket, send request.
- Make forms short, labelled and useful for operations teams.

## Reusable patterns

- `button`: primary command.
- `button ghost`: secondary navigation.
- `text-link`: compact contextual action.
- `service-listing-card`: a price-free engineering service capability card.
- `bucket-link`: persistent header entry point with selected-item count.
- `form-panel` and `bucket-summary`: framed request workflow surfaces.

## Accessibility requirements

- Every icon-only action needs an accessible name.
- Keyboard focus must be visible.
- Controls must have clear disabled states.
- Avoid using colour as the only indication of selected state.
- Honour reduced-motion preferences.
